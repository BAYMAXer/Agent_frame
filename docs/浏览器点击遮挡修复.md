# 浏览器点击遮挡修复

针对用户报告的最新两次运行 `173029`、`174104`，两类持续遮挡会使重复采集 AX 无效：搜索自动补全覆盖提交按钮，以及结果标题链接的包围框中心落在独立的翻译/详情控件上。本次依据用户给出的轨迹分析及本地源码定位问题，没有重新连接真实模型或访问 Google。

## 执行器处理

- 点击不再仅取包围框中心。优先检查目标中的标题和文本区域，再检查客户端矩形中的有限候选点；每个位置必须通过实际命中检测，确认点击会落在目标上。
- 目标内部另一个独立链接、按钮或输入控件不能作为该目标的点击位置，避免“点击标题链接”实际触发详情按钮。
- 选定位置在执行前复查。完整遮挡、目标移动、旧文档或失效引用仍拒绝执行，不使用强制点击或 JavaScript click。
- 仅在当前焦点输入框通过 `aria-controls` / `aria-owns` 关联可见自动补全列表，而且目标是该输入框或同表单的提交控件时，允许一次 Escape 关闭自动补全。之后重新核验页面和文档绑定，再定位目标并检查可点击点。没有自动提交 Enter。
- 模态、授权对话框、cookie 或无法确认关系的覆盖层交由当前子任务处理。返回 `error_code=target_occluded` 及遮挡者角色、名称、关联关系和建议，不自动关闭这些覆盖层。
- 弹窗检查覆盖隐藏弹窗之后的可见弹窗、相关 composed 祖先和可访问 Shadow DOM；检查未能完整完成时禁止自动 Escape。嵌套控件检查同时识别标准交互元素和可识别的独立 `onclick` 后代。

## 调度器处理

第一次确认遮挡后，下一轮直接提供浏览器 viewport 截图、扩大的 AX 和遮挡诊断。模型可以处理弹窗、改变滚动位置、选择实际标题节点，或在确认查询和焦点后用 Enter 提交搜索。

若后续仍点击同一页面、文档和 backend 节点，而且 AX 内容和浏览器画面都没有改变，程序先做一次只读命中复查，不发送点击、Escape 或滚动。若 CSS / `pointer-events` 等变化已经使目标可点击，仍可进入正常执行器复查；若遮挡持续，则阻止重复实际点击，返回 `occlusion_unchanged`。新快照 ID 不足以解除这一限制；画面或内容变化后也可重新检查目标。无效果的等待不会解除限制。恢复预算继续生效，真正未解决的遮挡以具体原因结束。

## 验证

真实 headless Chrome 与 localhost HTML 构造自动补全遮住整个搜索按钮、大标题链接中心被兄弟按钮覆盖、嵌套独立按钮、全覆盖模态及滚动后点击等情形；通过提交计数、实际目标网址和错误按钮点击计数检查结果。假模型流水线回归检查新快照不会绕过重复点击限制，以及拒绝后向模型提供截图和遮挡者信息。

新增真实浏览器测试共 11 项，包含多隐藏弹窗、Shadow DOM、独立内联点击处理器和只读 CSS 命中复查。测试均使用专用 headless Chrome、localhost 和假模型，不发送真实模型 API 或 Google 请求。

部署时将修改后的 `osworld_agent_1010` 同步到运行 Windows 环境并重启服务。验证覆盖代码机制，真实 Google 页面及真实模型任务仍需在实际环境运行后评估。
