# GUIworld 失败运行分析与修复

分析对象：另一台 Windows 导出的 `ui_20261013_144019_results.zip`。
任务是在 Google Scholar 下载 GUIworld 论文并保存到 `D:\paper`。
以下判断依据压缩包的 `trajectory.json`、`run_events.jsonl` 和截图；没有执行日志中的指令或连接真实模型。

## 实际原因

1. 第 3 步按 Enter 之前的 37 个 AX 节点仍属于搜索首页。Enter 之后的首次观察已经只有一个 `RootWebArea`，根名称仍是旧首页标题，而截图和页面标题已显示搜索结果。
2. 第 4～8 步复用完全相同的快照 `e128f68413d1`，没有重新采集。每次 `complete_subtask` 都提交空 `evidence_refs`，被硬性校验拒绝。
3. 每轮还对根节点快照调用选区模型。返回 `[0.19,0.09,0.67,0.99]` 不满足 `y+height<=1`，因此回退到仍为空的视口 AX，耗时约 9～15 秒。这不是 AX 字符预算截断导致的节点丢失。
4. 被拒的完成动作未进入浏览器恢复计数。重复动作检测先在第三次重复产生 STALL，再累积三次 STALL，所以实际重复五次才停。收尾逻辑把停滞写成“达到执行步数预算”，并把失败运行写成 `completed/unknown/error=""`。
5. 重复开窗来自两次页面创建：`ensure_chrome` 启动无痕空白窗口，`bind_owned_page` 再创建 context 和 target。

截图确实显示搜索结果，但可见顶部条目是 GUI world model 相关论文，尚不能确认指定论文 GUIworld 的身份。结果列表存在足以支持“搜索结果已显示”，不能直接支持“指定论文已找到或下载”。原计划猜测作者和系统 Downloads 路径也缺乏依据。

## 修复行为

- 新 CDP 会话在同一连接中有界重读 AX，最多 5 次、等待总计 825ms，并共享单步超时。采集期间文档或视口变化会重采集一次；持续变化拒绝观察，不混用旧节点。
- 原始观察记录 `ax_quality` 和 `ax_capture`。非空站点只有根节点时标为 `degraded`，保留本次 viewport 截图，跳过无意义的区域选择。
- AX 退化时决策和独立完成核验器接收当前浏览器截图。空引用只在有当前视觉证据时允许进入核验；快照绑定、引用合法性和程序下载校验仍然生效。标题、URL和模型声明本身不构成完成证据。
- 完成申请被拒后，下一轮由程序主动重新采集，并逐步扩大 AX / 使用浏览器视觉兜底。连续拒绝按 `early_stop_repeat` 停止，默认 3 次，保留具体失败原因。相同陈述和未改变的观察不重复调用完成核验器；同一快照的选区结果复用。
- 新启动实例通过专用 profile、端口 PID、唯一无痕空白 target 核验后，直接绑定启动页。导航和跨子任务复用该页。复用已有受管端点仍创建隔离 context；收尾仅关闭本任务拥有的页面。
- 失败运行写为 `status=failed`，提供 `termination_reason` 和 `error`。旧历史只读兼容映射，不重写原结果包。
- 规划禁止猜作者、论文身份、用户名和下载路径；下载要求实际落盘验证，后续文件操作使用前序结果的 `downloaded_file`。
- 工作台显示 AX 质量、读取次数、有效节点数及观察/恢复耗时。

## 验证方式与范围

回归使用假模型与固定本地页面，覆盖 Enter 后根节点退化、视觉完成核验、被拒后重新观察、重复完成限次、拒绝去重、无效区域缓存、旧快照和非视觉模型拒绝。

真实 headless Chrome / localhost 测试覆盖导航后的连续采集，以及首次绑定前后页面 target 数量保持为 1、跨子任务仅启动一次、收尾保留其它 context 页面。没有调用真实模型，也没有重跑 Google Scholar 下载任务；这些测试验证修复逻辑，不能代替该机器上真实任务的成功率评估。

将修改后的 `osworld_agent_1010` 同步到实际运行的 Windows 环境并重启工作台服务后生效；检查工作台与测试加载的版本目录均为 1010。
